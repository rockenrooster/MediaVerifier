# Audit, 2026-11-17

The owner's goal: review and audit for bugs, UI and UX, and fix every Critical and High until an audit pass finds
none. This is the record of the last two passes (rounds 10 and 11, after rounds 1 to 9), with the evidence for each
item.

**Rubric.** Critical: data loss or corruption, a crash or hang, a failed update. High: a core feature broken (a
button or setting that does nothing, a control that cannot be reached) or something misleading. Medium and Low:
everything else.

**Result.** Round 10 found four Highs and fixed them, with regression tests (v0.1.0.13). Round 11, a fresh pass on
that release, found no Critical and no High: one Medium (fixed) and one Low (recorded). No Critical or High is open.

## A. Freezes (UI thread waiting on disk, network, database or a process)

Every call of that kind in the app project, and where it runs.

| Call site | Runs on | Verdict |
|-----------|---------|---------|
| `ShellActions` (Open file, Open folder, Show in folder, pages, Licences) | its own STA thread | off the UI thread |
| `AddFolderDialog.CheckAndCount` (does the folder exist) | pool, after a 300 ms pause; 2 s notice, 15 s limit | off the UI thread; measured: an offline network folder takes 136 s to fail |
| `PathBox.StartFolderAsync` (Browse… start folder) | pool, 2 s limit | off the UI thread; test with an unreachable address |
| `CreateReportDialog.CreateAsync` (folder check, report) | pool | off the UI thread |
| `ToolsPage` licence text, quarantine sizes, database actions | pool (`LoadLicenceAsync`, `LoadTools`, `Run`) | off the UI thread |
| `UiServices.ScanController.StartAsync` / `ReevaluateAsync` | pool | off the UI thread; `Changing_a_rule_rejudges_the_library_off_the_ui_thread` fails against the old code |
| Page data (`LoadData` of every page), drawer evidence and thumbnails | pool | off the UI thread |
| `Remediator`, `DrawerActions`, `IssuesPage`, `LibraryPage`, `SchedulePage`, `ScansPage`, `DashboardPage` database reads | `Task.Run` | off the UI thread |
| `SettingsPage` self-check, system report | pool / separate process | off the UI thread |
| `UiServices.CreateLive` rule settings | before the window exists | not a window freeze |
| `PlanHost` waits | the headless scheduled run (no window) | not a window freeze |
| `UiWatchdog` | its own thread, debug builds only | not in the shipped app |

UI tests run with the database's UI-thread guard on (`Database.UiThreadId`, set in `Sta.Run`): a read on the UI thread
fails the test. All UI tests pass with it.
